0. Elevator pitch — học thuộc 3 phiên bản

30 giây (mở đầu):
“Em làm Project Sentinel — lab DevSecOps + AI hỗ trợ phân tích bảo mật trên OWASP Juice Shop chạy Docker Compose. Hệ thống quét SAST/DAST, chuẩn hóa finding, dùng AI agent đọc kết quả và kho tri thức để viết báo cáo, rồi gửi request thử an toàn qua API Gateway có allowlist, kèm chống prompt injection, HITL approve/reject và che PII. Mọi thứ chỉ nhắm localhost.”
2 phút (khung logic):
  1. Vấn đề: SAST/DAST ra nhiều cảnh báo nhưng thiếu ưu tiên + ngữ cảnh; pentest thủ công chậm; AI agent nếu full quyền thì nguy hiểm.
  2. Giải pháp: Pipeline lab: quét → gom data → RAG → agent phân tích → tool HTTP qua Kong → guardrail + HITL + PII.
  3. Chứng minh: CI chạy được; Kong deny 401/403/429; search “SQL Injection” ra tài liệu; syndicate E2E MOCK; Reject thì không gửi request.
  4. Giá trị học: Vận hành được DevSecOps + AI an toàn trong lab, không phải thay pentester.
Câu chốt (mentor nhớ 1 ý):
“Em không tin agent — em tin policy fail-closed: quyền nằm ở Kong/allowlist/HITL, không nằm trong system prompt.”

1. Vấn đề & giá trị (nói trước khi khoe tính năng)

Hình ảnh đời thường

Bạn có cửa hàng đồ chơi cố ý để lộ hàng (Juice Shop) để tập bảo vệ. Máy quét tìm ra nhiều chỗ nghi ngờ. Người đọc hết thì mệt. Bạn thuê robot AI giúp đọc và đề xuất bước tiếp — nhưng robot nhanh và dễ bị dụ, nên phải có cổng, thẻ, luật, và người lớn bấm “được phép”.

Đau thật trong AppSec
  • Finding SAST/DAST nhiều, thiếu ưu tiên
  • Pentest thủ công 3–10 ngày/app
  • AI agent full quyền = blast radius lớn
  • Junior cần lab an toàn để học
Sentinel mang lại
  • Baseline CI quét + data-lake
  • Agent triage + giải thích dễ hiểu
  • Gateway + allowlist + rate-limit
  • Guardrail / HITL / PII trong lab
ROI nói với mentor (trung thực): Giá trị chính là tốc độ học + pipeline tái sử dụng + thói quen AI an toàn, không phải “thay 100% pentester”. Lab MOCK LLM = demo ổn định, chi phí token ≈ 0.

9. Mentor hỏi gì — trả lời mẫu (học ý, đừng đọc máy)

Q1. Vì sao không để agent gọi thẳng :3000?
Trả lời
Vì quyền phải nằm ngoài model. Gateway tập trung auth/ACL/rate-limit/audit. Gọi thẳng app = agent bị hijack là full quyền app. Fail-closed ở Kong giảm blast radius.
Q2. Identity và capability khác nhau thế nào?
Trả lời
Identity = API key (recon vs exploit). Capability = được phép method/path nào (ACL + allowlist + path deny). Có thẻ chưa chắc được làm mọi thứ — giống thẻ nhân viên nhưng không vào phòng server.
Q3. RAG khác gì “nhồi hết tài liệu vào prompt”?
Trả lời
Nhồi hết = tốn token, nhiễu, dễ vượt context. RAG = retrieve top đoạn liên quan rồi mới generate. Em đo retrieval (P@3/MRR) để biết tủ sách có ích, không chỉ “có file markdown”.
Q4. MOCK LLM thì có phải gian lận demo không?
Trả lời
Không — mục tiêu lab là pipeline điều khiển an toàn + tái lập được. MOCK giúp mentor xem flow ổn định; có thể gắn OpenAI/vLLM sau bằng đổi base URL. Điểm chấm là kiến trúc + policy + evidence, không phải độ hay của văn LLM.
Q5. Prompt injection em xử lý thế nào?
Trả lời
Coi HTTP response / FTP content là untrusted. System prompt cấm đổi mục tiêu theo nội dung app. Thêm NeMo-style rails. Có artifact before/after. Không tuyên bố “chặn 100% mọi injection”.
Q6. HITL đặt chỗ nào trong flow?
Trả lời
Trước khi gửi POST / payload đặc biệt: hiện endpoint + payload + lý do → Approve/Reject. Reject → không gọi tool gửi request, có log. Có CLI và Slack-compatible local.
Q7. Payload “an toàn” nghĩa là gì?
Trả lời
Chuỗi dài, ký tự đặc biệt, rỗng, sai kiểu — để xem app phản ứng bất thường. Không dùng payload phá hủy, không đụng hệ thống ngoài Compose, không đổi dữ liệu production (vì không có production).
Q8. MCP khác REST tool thông thường?
Trả lời
MCP chuẩn hóa tools/list + tools/call: tool = capability có tên. Agent không được tự mở SQLite lung tung nếu policy là “chỉ qua MCP”. Tool lạ → deny.
Q9. Em đo success thế nào?
Trả lời
Compose up được; IAM deny-table xanh; RAG search ra đúng hướng; syndicate E2E; eval pipeline trên challenge giả lập; FinOps/monitor có số liệu; tài liệu runbook để người khác chạy lại.
Q10. Nếu chỉ còn 1 ngày trước deadline, cắt gì?
Trả lời
Giữ: parse+DB, 1 agent báo cáo, Kong+allowlist+tool, HITL, 1 test injection, README/demo. Cắt: GraphRAG, multi-agent đẹp, vLLM, dashboard observability. (PDF 6 tuần cũng xếp chúng là mở rộng.)
Q11. Khác gì chatbot bảo mật thông thường?
Trả lời
Chatbot chỉ nói. Sentinel có pipeline tool thật (scan→DB→RAG→HTTP qua gateway) + control plane (IAM, HITL, redact) + artifact kiểm chứng. Mentor có thể verify bằng lệnh, không chỉ nghe kể.
Q12. Rủi ro lớn nhất của hệ thống này?
Trả lời
Agent bị dụ + tool quá mạnh + người tắt HITL. Mitigation: localhost-only, Kong least privilege, allowlist, rate-limit, guardrail, HITL mặc định cho hành động nguy hiểm, PII redact.

10. Giới hạn — nói trước khi mentor chỉ ra

  • Lab-only: không phải sản phẩm pentest production.
  • MOCK LLM: chất lượng ngôn ngữ không phải điểm bán chính.
  • Juice Shop cố ý lỗ: CI “đỏ finding” là bình thường; pipeline không fail vì tìm ra lỗi.
  • Injection defense cơ bản: không claim chống mọi jailbreak.
  • GraphRAG/multi-agent: prototype học tập, chưa scale enterprise.
  • Không thay pentest thủ công chuyên sâu / red team thật.

Câu kết giới hạn: “Em tối ưu cho học và kiểm chứng control, không oversell.”
